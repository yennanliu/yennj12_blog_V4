## Batch summary

This batch splits cleanly into two populations. The six English "comprehensive guide" posts (microservices, optimizing-db, sharding, webhooks, typescript, express) have no thesis — five open with "This comprehensive guide explores…" and the sixth with an unattributed first-person war story ("we had a monolithic application serving millions of users", microservices L17) — and they reach depth only where a later retro-patch was bolted on (the sharding cross-shard warning L1268, the consistent-hash ring L368, the webhook raw-bytes note L338, the Express 5 / ESLint 9 / Node 22 notes L699/L1416/L1473, the `const enum` note typescript L422). The patches are the best paragraphs and each sits beside unrevised code. The dominant defect is the same one B22/B23 found: **code that does not compile, does not run, or does not do what the prose says, presented as production patterns** — `sql.OpenDB(connector, config)` with a non-existent `sql.Config` (microservices L281-288), a singleton `JdbcTemplate` whose `DataSource` is swapped per request so concurrent calls hit the wrong shard (sharding L201/L467/L908), a Stripe handler that casts a Jackson `LinkedHashMap` to `PaymentIntent` (webhooks L1065) behind a default `ObjectMapper` that rejects every real payload, an Express JWT branch that can never run because `TokenExpiredError` is a subclass of the error caught first (L544-546), and a response cache keyed on URL alone that will serve one authenticated user's `/users` list to the next (L1134-1157). Unsourced numbers are rarer than in B23 — optimizing-db is the only post with a "Results" section and it is now labelled illustrative (L521), but its title still promises "Sub-millisecond" while the labelled result is a 50 ms p95 (L2/L13 vs L526).

The three Traditional-Chinese posts are a different story. The shopping-cart pair is the best-written material in the batch: a real thesis each ("高並發需要系統性地消除每一層的瓶頸" part 1 L605; "鎖必須包在事務外面" part 2 L176-200), a what-to-cache table with the reasons *not* to cache (part 1 L224-233, L537-545), the `LazyConnectionDataSourceProxy` timing explanation (part 2 L457-492) and the `jakarta.transaction.Transactional` trap (L499-512) are the kind of flip-condition writing the writer skill asks for, and both PRs exist, are merged, and contain the lock keys, TTLs and routing code the posts describe. But part 2's own `CartService` holds the Redisson lock *inside* a class-level `@Transactional` (L101-126) — exactly the "錯誤設計" the post diagrams 50 lines later — and the lock still issues an unconditional `INSERT`, so the duplicate-row race it is introduced to fix (L41-52) is unchanged; its nginx block puts `limit_req_zone` inside `server {}` (L660-665), which nginx rejects at startup; and its Dockerfile ships `eclipse-temurin:17-jre` (L693/L701) for a series whose first line of config says `REQUIRES Java 21` (part 1 L123). The Spotify post is a repo tour whose 2026 retro-note (L16) admits there is no trained model, after which the body claims "基於機器學習" / "深度學習" six more times and adds a Redis, nginx and JWT stack the README does not contain. The Chinese prose is natural Taiwanese Mandarin throughout (執行緒/連線池/快取/資料庫), with two stray simplified glyphs in Spotify (L210 趋势, L588 僾). The English is fluent brochure register with no machine-translation artefacts.
