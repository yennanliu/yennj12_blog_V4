- 15-1: Long-horizon agents are a reliability-engineering problem — checkpoints and idempotency handle crashes, per-step verification and drift detection handle compounding errors.
- 15-2: Self-improvement (Self-Refine, CAI, RLVR) and the safety stack must be co-designed, with defense in depth from input gateway to action sandbox.
- 16-1: Coordination cost, not agent count, is the multi-agent bottleneck; pick the coordination pattern first.
- 16-2: Emergent collective reasoning (debate, MoA) is a designable protocol whose risk is loss of control, so monitor and route rather than always run it.
- 17-1: Inference serving is a systems problem (framework, batching, GPU sharing, cold start, tenancy), and utilisation is the cost lever.
- 17-2: AI observability must track semantic quality, prompt/model versions and cost per token, not just latency and errors.
- 17-3: AI cost is an engineering problem solved by cache, routing, batching and prompt caching, not by procurement.
- 18-1: AI safety is an SRE problem with SLOs, measured failure rates, layered defenses and continuous red-teaming.
- 18-2: Governance is a system component — translate regulation into fairness metrics, privacy budgets and audit artefacts in CI.
- 19-1: RAG is a system (parsing, hybrid index, rerank, eval, observability), not a script.
- 19-2: A production agent is ReAct + tool safety gate + memory + guardrails + observability, and side-effecting tools are the pressure point.
- 19-3: Multimodal apps are a latency-budget, routing and degradation design problem, not a model-capability problem.
